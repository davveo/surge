# Web IM 百万在线技术方案

对标微信网页版：单聊 + 群聊。接入层与业务层分离，消息正文只存一份会话时间线，用 `seq` 做断线补齐。

**目标是 100 万同时在线长连接，不是 100 万注册用户。** 瓶颈在长连接和群消息扇出，不在 HTTP QPS。

## 核心原则

1. 网关只持有 TCP，业务不持连接。连接扩容不能拖垮落库。
2. 会话时间线存正文一次；inbox 只存指针，禁止把群消息正文复制 N 份。
3. 投递语义是至少一次；客户端用 `client_msg_id` 去重。
4. 图片和文件禁止走 WSS，只走预签名直传 OSS。
5. P0–P2 不做朋友圈、支付、小程序、音视频。

## 阶段速览

| 阶段 | 周期 | 同时在线 | 编制 | 目标 |
|---|---|---|---|---|
| P0 可用单聊 | 6–8 周 | 1 万 | 4 人 | Web 能稳定发文字、看会话、断线可补齐 |
| P1 群聊与媒体 | 8–10 周 | 10 万 | 5–6 人 | 接近微信网页版日常使用 |
| P2 百万在线 | 10–14 周 | 100 万 | 6–8 人 | 长连接水平扩展，分片与异步扇出 |
| P3 平台化 | 持续 | 300 万+ | 平台组 | 搜索、多地接入、音视频、开放能力 |
